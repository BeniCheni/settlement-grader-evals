GAPS IN THE SPEC THIS PROMPT RESOLVES, each named in the PR body under "Resolution". (1) Retrieved items. A lookup_rule item's topic is its result's "topic", the topic lookup_rule resolved, so the alias variant is credited with the rule it fetched; a rule_error item's topic is the call's args "topic" as given. A get_match_facts item's id is str of its result's "event_id"; a result with an error or with no event_id gives none. An item repeats when its (kind, id) pair does. (2) Needed items are the distinct (kind, id) pairs in the order of the row's contexts, first occurrence kept. (3) Faithfulness, per leg of the row. Its facts are _best_facts of the record's ticket leg over _facts_seen(record); its key is key_for_leg of the row's leg on those facts. The facts are usable when _best_facts returned some and key_for_leg did not raise KeyError, TypeError or ValueError on them; any other exception propagates. In this order: with no usable facts, a committed grade is supported only when it is NEEDS_HUMAN; with usable facts and a key of None, the leg leaves the rate entirely, its score claims with it, and is counted (ruling 26); a MOOT grade is supported when another leg has a committed L; any other grade is supported when it equals the key. A leg is one claim when _committed gives it any grade, and it is supported when every grade committed for it is. A score claim is each distinct score in the evidence of every final leg whose "leg" equals that leg's number: two runs of one or two digits joined by a hyphen or an en dash, spaces allowed around it, with no digit, hyphen or en dash directly before or after, so the 10-14 inside 2026-10-14 is not a score. It is supported when it equals, either way round, one of score_regulation_90, score_halftime and score_final in the facts _best_facts returned, usable or not; with no facts it is unsupported. The rule on a raise is the PM seat's: a run that never fetched the fact a market settles on made that grade without facts. In five of the six recorded runs, B05's leg 4, "1st Half Total Goals", has only a find_match full-time score as its facts, and key_for_leg raises KeyError on score_halftime there. (4) answer_relevancy. A final that is not a dict scores 0. Legs that are not a list count as an empty list. The numbering test needs each entry to be a dict whose "leg" is its position, 1 to n. ticket_result is compared exactly with WIN, LOSS, PUSH, VOID, UNSETTLED and NEEDS_HUMAN, and exactly with the ticket_result of the last settle_ticket call whose result has no error; with no such call that test fails. (5) Returns. Each of the four public scorers returns a float or None and nothing else, so Braintrust can call it. score_case(row, record) returns each scorer's value with its reason, plus faithfulness's claims, supported claims and legs left. The public scorers and score_case run one code path. (6) The config before v1. dataset is "data/golden/v1.jsonl", model "qwen3:8b", and dataset_sha256 null until the PM seat writes v1's hash into it after the freeze; if v1 is on main when you build, write its hash instead. A test holds it: when dataset_sha256 is not null it equals the hash in data/golden/v1.sha256, and while it is null nothing fails, so a freeze never turns the suite red (ruling 34). Every object holds exactly its written keys, as the contract says, and a value of the wrong type is refused too: rule_match exact or alias; a run id matching ^[A-Za-z0-9][A-Za-z0-9._-]*$; n_boot a positive int and seed an int, neither a bool; each bar a number, not a bool; each path a string. Every path in the config is relative to the repository root, found from the module's own location, never the working directory. (7) run. Refused with status 2, one line on stderr, nothing written and no model called: a config the contract refuses; a --variant other than a or b; dataset_sha256 null, v1 missing, or v1's bytes not matching it; traces/<the variant's run id> already existing. Otherwise it calls run_eval.main in process with [dataset, "--run-id", the run id, "--model", model, "--rule-match", the variant's rule_match] and returns its status. A test replaces run_eval.main and reads that list; no test lets it run. (8) report's refusals, beyond the spec's, each with status 2, one line on stderr and nothing written: dataset_sha256 null or v1's bytes not matching it; a run directory, its run_meta.json or its settlement-traces.json missing; model_digest or ollama_version missing from either run's run_meta (the recorded runs traces/v1 and traces/aa-1 to aa-3 lack both); a run_meta whose model differs from the config's, whose cases_file differs from dataset, or whose rule_match differs from its variant's; two records for one case in a run, or a record for a case v1 does not hold; a record whose ticket differs from json.loads of its row's question, as pilot refuses; and the statement file missing or blank. (9) The report's numbers. Each mean and interval bound is printed to three decimals and each count as an integer, with the verdict words fixed in the module. reports/rag.json is written through stats.canonical_json. Cases go in case_id order, and no stake, price, payout or net is printed. (10) The bars, from the config's bars. Recall holds when the interval's lower bound is greater than recall_lo_above; faithfulness when its lower bound is at least faithfulness_lo_at_least; outcome when paired_difference's upper bound is at most outcome_fall_hi_at_most. Outcome uses outcome_match called as run_eval.main calls it, with a the cases both variants match, b those only A matches, c those only B matches and d neither. A bar with no pairs, or a paired_difference of None, does not hold. Each metric pairs the cases where both variants scored it, and the report prints how many left. (11) The weaker half. A tie, or a half with no scored case, names neither half and says why. (12) The groundedness candidates print A's four scores and the tool_calls of A's record, in case_id order. (13) The statement, reports/rag-statement.md, is the PM seat's, written after the runs. This PR commits none, and the tests use a fixture. (14) The stale test, on freeze's pattern. While traces/w4-a or traces/w4-b is absent, the config's report and json files must be absent; once both runs are present, the committed files must equal report's output byte for byte. A second test proves on temporary files that the first can fail. (15) The Braintrust uploader. It sits outside scorer/ and the tests, never imported by either, as uploaders/langsmith_pin.py does, and its test reads its source only, as tests/test_langsmith_pin.py does. Before it imports braintrust it refuses when the config is refused, v1's bytes do not match dataset_sha256, or a run is missing. It reads its key from the environment and prints no part of it. It makes one Eval per variant in the project settlement-grader-rag, named for the run id. The data are v1's rows, each as input question, expected ground_truth and metadata {question, ground_truth_contexts, row}. The task returns the recorded output {answer, retrieved_contexts, record} for the case and calls no model. The scores are the four public functions. The PR body carries the dependency paragraph AGENTS.md asks for and cites Braintrust's documentation for each call. It never runs in this PR. (16) Paths.
