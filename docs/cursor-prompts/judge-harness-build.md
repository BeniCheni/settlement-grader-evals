WHY THIS PR EXISTS. The course's Week 2 asks for three LLM judges, each shown to agree with a human before it is trusted. This repo already measures that agreement for its plain-code checks. This PR adds what a judge needs around it, as docs/judge-spec.md specifies: rubric files read and hashed, a case file for each grader output, a label sheet the owner fills in by hand, a call to a local model through Ollama, a strict reading of the reply, a report of each judge against the owner's labels, and the export of the course's files. It is the harness only. No rubric, label, model download or real judge run is in it, and its tests call no model.

THREE GAPS IN THE SPEC THIS PROMPT RESOLVES, each named in the PR body under "Resolution". (1) How a run is named. Every file that names a run (the plan, the labels, the fake-reply keys, the readings keys, the verdicts, the meta files and the reports) names it as a relative path with forward slashes and no trailing slash, normalised so that ./traces/v1/ and traces/v1 give the same bytes: traces/v1. An absolute path is a usage error, because it would put a machine path in a committed file. (2) The unsure cell. In labels.csv it holds rubric names separated by semicolons, each trimmed, and an empty cell means none. import-labels writes them in sorted order, and refuses a duplicate as well as a name that is not a rubric. The first line of case-files.md says so. (3) Writing nothing on an error includes run. It writes verdicts.jsonl and judge_meta.json only after every reply is in hand, so a connection failure at the hundredth call leaves no file behind. Resuming a partial run is out of scope.

HAZARDS THE PM SEAT KNOWS ABOUT, to check and not to trust. (a) The spec's size figures (892 to 9,679 characters) measure the ticket, tool calls and final answer as one compact JSON object, not the rendered case file, which indents the ticket and the final answer. Print the shortest and the longest rendered case file on traces/v1 and on traces/smoke-1, on both Pythons, in the PR; if any is over 24,000 characters, stop and say so. (b) The golden case file copies a tracked trace. Six of the 32 records of traces/v1 contain a dollar sign followed by a digit in their ticket, tool calls, final answer, status or reason (scaled amounts that are already tracked). A01, which has one call to each of the four tools, no tool error and a final answer, has none, so the PM suggests it. Whatever you pick, the privacy sweep reports the golden file's hits on a line of their own, and nothing computes on an amount. (c) traces/v1 has six records with no tool call (B06, B10, C02, C03, C14, X02) and three whose final is null (B05, B08, C14), so the "none" forms of the case file can be shown on real records as well as fixtures. (d) The spec forbids "held out" in any computed part of the report, and that includes a negation: "not held out" fails the test too. The phrase may appear only inside the reproduced provenance file. (e) AGENTS.md: meets_bar tests the two numbers only. The report prints the false passes read (has_reading over the readings, as k of n) beside it and never folds that in, and no sentence or label presents the numbers alone as the trust verdict. Reuse bar_words to name the bar. (f) A kappa that cannot be computed (stats.cohen_kappa returns None) ranks lowest, prints as such, and is null in the JSON. (g) export-course puts each rubric verbatim in a fenced block. A rubric may contain backticks, so the fence must be longer than any run of backticks in it, and a test proves it. (h) The owner may fill labels.csv in a spreadsheet app, which can save a byte-order mark or CRLF line ends. Decide whether import-labels accepts them, test the decision, and say it in the PR; either way the spec's "exactly PASS or FAIL" stands for every cell. (i) Each label row carries a trace_id. When a command loads a run for a row and the record for that run and case_id has a different trace_id, the run changed after labelling. Decide how that is treated (the PM's reading is a refusal with status 2), test it, and say it. (j) Every SHA-256 is of the file's bytes as stored. (k) An input that is missing, unreadable or not valid JSON is a validation error like any other: status 2, one message, no traceback, nothing written. That includes the Ollama adapter's connection failure, and an /api/tags or /api/show reply that lacks the model. (l) pick-model takes the grader model's family from /api/show for the model in the grader run's run_meta.json (qwen3:8b for traces/v1). If that call fails or has no details.family, the command stops with status 2 and never assumes a family. Whether pick-model stops at the first candidate that parses or runs every candidate is yours; model-choice.json records each candidate it ran and names those it did not. Tests inject a fake /api/show and fake replies, and how the injection reaches the command is yours. (m) Every generated file is the same bytes on 3.9 and 3.14. Reuse canonical_json for JSON, write JSONL with sorted keys, and use nothing newer than 3.9: no zip(strict=...), no match, no X | Y annotations, no parenthesised context managers. (n) tests/test_provenance_words.py scans scorer/*.py for four retired phrases ("fixed while reading", "checks were fixed", "were tuned on", "tuned on traces"), so your module must not contain them. (o) grader/espn.py prints a ResourceWarning under unittest when it opens the frozen file. That is out of scope, so do not fix it.
